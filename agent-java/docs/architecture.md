# Java runtime architecture

The native Java runtime targets [contract 2.0.0](../../contract.md), schema 6 and the applicable [design update](../../design_update.md). Shared operator qualification is separate from the isolated Java regressions.

`ConfigRepository` resolves trusted relative YAML profiles, expands string values after parsing, validates policies/graphs/schema assertions and freezes source and resolved identities. `JsonSupport` keeps RFC 8785 command/action/commit identities distinct from the existing Python-style sorted config/projection/archive hashes. The fixed shared identity vectors are regression inputs.

`AgentController` normalizes and strictly validates keyed requests before admission. `CommandStore` uses the unique namespace/client/key tuple to arbitrate duplicates, freezes admission, renews command leases and replays stored terminal responses. Commands are claimed before sessions; every save checks both authorities. Duplicate streams return JSON handles/responses. Event reconnection only reads the committed ledger.

`ExecutionCoordinator` claims the session and then hydrates authoritative state, maintains a separate heartbeat and schedules cooperative cancellation at boundaries. Every run has one origin command. Intent and a started attempt commit before dispatch. Tool results, correlated messages, evidence, artifacts, execution/attempt settlement and state commit together. Recovery retains the original action/run/key/payload and records new recovery-command attempts. Read-only/repeatable policies permit their specified recovery; effectful actions require an actual keyed adapter or authoritative verification. Unknown, expired or ambiguous outcomes block. The controlled fixture recipient atomically stores its effect and keyed receipt in the fixture database.

`AgentEngine` executes every returned call in order with typed argument validation and a fixed phase policy for each batch. Workflow evidence is captured only from executed results. Completion checks include final-only tool exclusion, exact/pattern/schema requirements, forbidden content and captured table/number/JSON artifacts. Result bindings use captured values. Consecutive invalid responses and no-progress decisions have separate durable counters.

Compaction budgets the actual adapter request, output reserve and margin. It retains immutable anchors and complete recent interaction groups, selects an affordable historical prefix, and applies cadence/growth/spacing/pressure/reclaimable/reduction policy with immediate hard-budget protection. Proposals are normalized to four canonical sections, restore the original goal, reject unsupported numbers and truncation, and remain unverified model claims. Replacement is staged and must reduce the complete request. Accepted/rejected provenance records preserve source identities/hash, prior ledger and retained identities. Evidence/artifacts are outside compacted claims. Diagnostics retain bounded hot tails and lifetime counts.

`SessionRepository` writes each aggregate in one JDBC transaction on a blocking worker: snapshot, immutable transcript/call identities, active context, diagnostics, runs, executions, attempts, events and commit receipt. Receipt lookup precedes revision conflict handling, including lost-ack retries and historical receipts requiring reload. Immutable config/goal, source provenance, active hashes and revisions are checked; stale authority cannot overwrite a newer owner. Active hydration is one MVCC statement with bounded diagnostics. Explicit history APIs use bounded cursors/watermarks.

`SchemaValidator` performs read-only structural validation against the pinned schema manifest. `StartupRecovery` reconciles abandoned metadata without executing user work. `RetentionAdmin` exports/verifies canonical archives and performs explicit fenced telemetry-only pruning. Default retention is keep-all. The server never creates or changes database schema objects.

JSON and SSE runs execute independently of HTTP cancellation so an in-flight invocation can finish and retain its known outcome. Terminal events are exposed only after terminal task/run state commits. Worker loss leaves durable pending/started evidence for explicit recovery.
